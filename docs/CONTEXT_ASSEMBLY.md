# Graph-derived context assembly

`COMBE_CONTEXT_PACKAGE` version 1 is a provider-neutral projection, not stored state. `ContextAssembler::assemble` accepts a Work ID, Recipient ID, message, maximum item count, and maximum byte count. It resolves the Recipient and Provider profile, verifies the current `COMBE_CONTEXT_GRAPH`, traverses only the addressed Work scope, and emits stable Context items.

Items contain identity, kind, concise display and reference values, graph-source provenance, relevance, and explicit selection reasons. Work and current Worktree lead. Decisions, files, commits, conversations, provider exchanges, artifacts, messages, and context snapshots retain graph order. Deterministic lexical matches from the current message promote related items inside their graph category; vague messages retain the graph fallback order. Stable identity breaks ties.

File Context items retain references and may include bounded UTF-8 content from regular files resolving inside the registered Worktree. Selection combines graph relationships, common repository orientation files, lexical path relevance, source-tree location, file importance, and stable path ordering. Assembly never scans beyond that Worktree, includes raw provider payloads, or resolves credential references. Sensitive paths, credential-shaped content, generated/dependency directories, binaries, and escaping symlinks are excluded. Item, reference-byte, content-byte, per-file, and serialized-package budgets are applied before delivery; inclusion, reference-only, unavailable, and excluded outcomes are explicit.

The package fingerprint covers its canonical provider, model, Recipient, Work revision, graph fingerprint, message, assembly policy, ordered items, content outcomes, and content hashes. It excludes credentials, raw file copies outside the transient package, and operational generation time. Provider adapters receive a `ProviderRequest` containing the assembled package and worktree; adapters do not query the graph or read files. Direct HTTP, local CLI, and external-manual providers therefore receive the same logical package. Durable provider exchange provenance stores the fingerprint and ordered item identities, not another copy of the package.

The Work surface's **View Context…** action displays the exact package inputs, references, reasons, bounds, and fingerprint. Send invokes that same assembly boundary again. If durable state changed between inspection and Send, the new fingerprint makes the change explicit in provenance. Missing graph state is initialized once; stale or unhealthy graph state blocks delivery and directs the user to `combe graph rebuild`.

CLI equivalents are `combe context preview`, `combe context inspect`, `combe context fingerprint`, and `combe context diff`. Each accepts the Work and Recipient explicitly, and supports JSON for tooling.
